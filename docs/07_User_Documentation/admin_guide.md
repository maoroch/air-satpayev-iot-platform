# Руководство администратора и технического специалиста

**Проект**: Цифровая система мониторинга и управления устройством очистки воздуха  
**Заказчик**: НАО «Казахский национальный исследовательский технический университет имени К.И. Сатпаева»  
**Версия системы**: 1.0.0 (2026 г.)

---

## 1. Ролевая модель и разграничение прав (RBAC)

Система поддерживает 3 предустановленные роли с жесткой проверкой на сервере:
1. **Администратор (`ADMIN`)**:
   * Регистрация новых приборов в системе;
   * Настройка нормативного ресурса фильтра;
   * Управление пользователями;
   * Полный доступ к журналу аудита действий;
   * Экспорт данных.
2. **Оператор (`OPERATOR`)**:
   * Просмотр показаний, графиков и уведомлений;
   * Отправка разрешенных команд управления вентилятором;
   * Фиксация факта замены фильтра со сбросом наработки;
   * Экспорт отчетов.
3. **Технический специалист (`TECH`)**:
   * Просмотр диагностической информации микросервисов;
   * Анализ брокера сообщений MQTT и очереди пакетов;
   * Контроль аппаратных параметров контроллера (RSSI, WDT, I2C).

---

## 2. Управление системными параметрами и пороговыми значениями

### 2.1. Ресурс фильтра
По умолчанию нормативный ресурс равен **720 моточасам** (30 суток непрерывной работы прибора). Настройка передается в карточке прибора `filter_hours_max`. При превышении 90% вырабатывается предупреждение `FILTER_WARN`, при 100% — критический алерт `FILTER_EXPIRED`.

### 2.2. Таймаут связи (Heartbeat)
Если устройство не передает пакеты телеметрии дольше **30 секунд**, система автоматически переводит статус прибора в `OFFLINE` и формирует единичное уведомление о потере связи без спам-дублирования (FR-10).

## 3. Резервное копирование и восстановление базы данных

Для проведения планового резервного копирования используется утилита `scripts/backup_restore.sh`:

```bash
# Создание полного дампа БД
./scripts/backup_restore.sh backup

# Восстановление базы данных из дампа
./scripts/backup_restore.sh restore ./backups/backup_purifier_db_20260918_153000.sql
```

---

## 4. Диагностика микросервисов и журнал аудита

1. **Диагностика**: Перейдите во вкладку **«Диагностика оборудования»** в веб-интерфейсе для проверки доступности портов 8000 (API), 1883 (MQTT), 5432 (PostgreSQL) и 6379 (Redis).
2. **Журнал аудита**: Во вкладке **«Журнал аудита»** фиксируются все значимые операции с указанием времени, почты пользователя и IP-адреса.
