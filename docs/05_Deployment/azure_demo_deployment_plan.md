# 📋 План развертывания проекта в Microsoft Azure (Demo-стенд)

> **Назначение**: Публичная демонстрация цифровой платформы мониторинга очистителя воздуха для заказчика (НАО «КазНИТУ им. К.И. Сатпаева»).  
> **Ключевой приоритет**: Минимальные финансовые затраты, мгновенный запуск перед показом и надежность работы всех 6 микросервисов.

---

## 1. 💰 Экономическая модель и стратегия затрат

В Azure виртуальные машины тарифицируются **посекундно (Pay-as-you-go)**. Для демонстраций не требуется держать сервер включенным 24/7.

### Сравнение затрат:

| Сценарий использования | Часов в месяц | Стоимость (`Standard_B2s`, 4GB RAM) | Стоимость в тенге (₸) |
| :--- | :--- | :--- | :--- |
| **Круглосуточная работа (24/7)** | 730 часов | ~$35.00 / мес | ~17 500 ₸ |
| **Режим демонстраций (20 часов)** | **20 часов** | **~$0.96 суммарно** | **~480 ₸** |
| **Режим демонстраций (50 часов)** | **50 часов** | **~$2.40 суммарно** | **~1 200 ₸** |

> **Принцип нулевого простоя бюджета**:  
> Когда ВМ переведена в статус `Deallocated` (командой `az vm deallocate`), вычислительные ресурсы (vCPU и ОЗУ) **не тарифицируются вообще**. Оплачивается лишь хранение диска (~$1.5 в месяц / ~750 ₸).

## 2. 🖥️ Характеристики сервера и выбор региона

### Выбранный регион:
* **Регион**: **Центральная Индия (`centralindia`)**
* **Причина выбора**:
  1. Один из наиболее бюджетных регионов Azure.
  2. В вашем аккаунте уже есть активные ресурсы в этом регионе (`rg-b2b-leads-india`, `rg-financeos-prod`), что гарантирует наличие квот и отсутствие задержек на верификацию подписки.

### Конфигурация виртуальной машины:
* **Размер (SKU)**: **`Standard_B2s`** (Burstable B-series)
* **Процессор (vCPU)**: **2 ядра** (Intel Xeon / AMD EPYC)
* **Оперативная память (RAM)**: **4.0 GB**
* **Операционная система**: **Ubuntu Server 24.04 LTS (x64)**
* **Диск**: 30 GB Standard SSD / Premium SSD

## 3. 🌐 Сетевая топология и публичные порты

Сервер получает постоянный публичный IP-адрес со статическим DNS-именем:  
🔗 **`http://satpayev-air.centralindia.cloudapp.azure.com`**

### Правила Network Security Group (NSG):

| Порт | Протокол | Назначение | Доступ |
| :--- | :--- | :--- | :--- |
| **80 / 3000** | TCP | Веб-интерфейс мониторинга (Next.js Dashboard) | Публичный (для заказчика) |
| **8000** | TCP | Документация REST API (Swagger UI / ReDoc) | Публичный |
| **1883** | TCP | Брокер сообщений MQTT (Mosquitto) | Для подключения ESP32 / эмулятора |
| **22** | TCP | Защищенный SSH-доступ администратора | По SSH-ключу |

## 4. 🚀 Пошаговый план развертывания (Этапы)

### Этап 1. Инициализация инфраструктуры в Azure
1. Создание отдельной группы ресурсов: `rg-satpayev-air-demo`.
2. Создание группы безопасности сети (`nsg-satpayev-air`) с открытыми портами 22, 80, 3000, 8000, 1883.
3. Выделение публичного IP с DNS-лейблом `satpayev-air`.
4. Создание виртуальной машины `vm-satpayev-air` с привязкой существующего SSH-ключа (`~/.ssh/azure_vm_new_key.pub`).

### Этап 2. Автоматическая настройка сервера (Provisioning)
1. Обновление пакетов Ubuntu (`apt update && apt upgrade -y`).
2. Установка Docker Engine и Docker Compose v2.
3. Настройка файла подкачки (Swap 2 GB) как дополнительной подушки безопасности.
4. Настройка автозапуска Docker-демона при старте сервера.

### Этап 3. Развертывание стека проекта
1. Клонирование репозитория на виртуальную машину.
2. Проверка переменных окружения `.env` (JWT Secret, Mosquitto, PostgreSQL credentials).
3. Сборка и запуск контейнеров в фоновом режиме:
   ```bash
   docker compose up -d --build
   ```

### Этап 4. Приемочный контроль и валидация
1. **Проверка дашборда**: вход под учетной записью администратора `admin@satpayev.kz`.
2. **Проверка телеметрии**: поступление пакетов от эмулятора, генерация графиков в реальном времени.
3. **Проверка REST API**: вызов `/api/v1/system/diagnostics` и Swagger UI на порту 8000.
4. **Проверка WebSocket**: индикатор «В сети» и отсутствие задержек на дашборде.

## 5. 🛠️ Памятка по управлению сервером (Шпаргалка)

### 1. Запустить сервер перед демонстрацией (за 40 секунд):
```bash
az vm start --resource-group rg-satpayev-air-demo --name vm-satpayev-air
```

### 2. Заморозить сервер сразу после показа (остановить начисление денег):
```bash
az vm deallocate --resource-group rg-satpayev-air-demo --name vm-satpayev-air
```

### 3. Проверить текущий статус сервера:
```bash
az vm get-instance-view --resource-group rg-satpayev-air-demo --name vm-satpayev-air --query "instanceView.statuses[1].displayStatus" -o tsv
```
